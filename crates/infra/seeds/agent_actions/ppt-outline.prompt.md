# Markdown 大纲 schema（必须严格遵守）

输出文件格式：

```markdown
---
title: <主题>
audience: <受众，如「产品经理」「技术评审」「内部分享」>
duration_min: 30        # 驱动页数预算：15min≈10页 / 30min≈20页 / 45min≈25-30页
style: A                # A=电子杂志风 / B=瑞士国际主义风
---

## P01 · Hook · <页标题>
- 一句话要点
- 一句话要点

## P02 · Context · <页标题>
- ...

（按叙事弧 Hook → Context → Core → Shift → Takeaway 组织，页数与 duration_min 匹配）
```

## 叙事弧骨架（参考 guizang-ppt-skill）

按下面 5 段组织 H2，页数与 `duration_min` 对应的页数预算匹配：

| 段 | 页数预算 | 内容 |
|---|---|---|
| 钩子 (Hook) | 1 页 | 反差 / 问题 / 硬数据，让人停下来 |
| 定调 (Context) | 1-2 页 | 背景 / 你是谁 / 为什么讲这个 |
| 主体 (Core) | 3-5 页（按时长放大） | 核心内容，每页聚焦一个论点 |
| 转折 (Shift) | 1 页 | 打破预期 / 提出新观点 |
| 收束 (Takeaway) | 1-2 页 | 金句 / 悬念问题 / 行动建议 |

## 每个 H2 的硬约束

- 标题简洁（5-10 字），格式严格：`## P{两位页号} · {叙事弧段} · {页标题}`
- H2 下面 2-3 个 bullet，每条一句话（不要段落、不要长篇大论）
- 这是给后续「PPT 制作」用的**结构骨架**，不是演讲稿——保留原文关键数据/术语，不要编造

# 强制停止指令（重要）

# 文件读取约束

- 若传入的是**文件夹**：递归列出文件（`ls -R` 或 walk），跳过 `.git` / `node_modules` / 二进制文件（图片/视频/可执行文件）
- 若传入的是**多个文件**：阅读每个文件后**统一规划大纲结构**，不要每文件一页
- 若只有音频/视频文件：先转写（可调用系统 ASR 或下载工具），再用文本生成大纲
- 若文件含敏感信息（API key、密码），**不要写进大纲**，并在最后告知用户跳过了哪些内容
